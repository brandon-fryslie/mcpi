### Key Architectural Innovation: InlineEnableDisableHandler

**CRITICAL**: Cline is the FIRST client to use the InlineEnableDisableHandler pattern:
- **Previous clients** (Claude Desktop, Windsurf): FileMoveEnableDisableHandler
  - Disable: MOVE server config from `config.json` → `config_disabled.json`
  - Enable: MOVE server config back to `config.json`

- **Cline** (new pattern): InlineEnableDisableHandler
  - Disable: ADD `"disabled": true` field to server config object
  - Enable: REMOVE `"disabled"` field from server config object
  - All servers stay in the same file

**Why This Matters**:
- Cleaner for single-file configs (no shadow file needed)
- More intuitive for users (disabled servers visible in config)
- Better for version control (single file to track)
- Aligned with VS Code extension patterns

**Config Example**:
```json
{
  "mcpServers": {
    "enabled-server": {
      "command": "npx",
      "args": ["-y", "some-package"]
    },
    "disabled-server": {
      "command": "npx",
      "args": ["-y", "other-package"],
      "disabled": true  // ← Added by InlineEnableDisableHandler
    }
  }
}
```

## Architecture Evolution

### Enable/Disable Handler Patterns

We now have TWO proven patterns for enable/disable functionality:

#### Pattern 1: FileMoveEnableDisableHandler
**Used by**: Claude Desktop, Cursor, VS Code, Windsurf

**Behavior**:
- Active servers: `config.json` (or equivalent)
- Disabled servers: `config_disabled.json` (shadow file)
- Disable operation: MOVE server from active → disabled file
- Enable operation: MOVE server from disabled → active file

**Best for**:
- Clients without native disable mechanism
- When disabled servers should be "out of sight"
- Simpler config file (only active servers visible)

#### Pattern 2: InlineEnableDisableHandler
**Used by**: Cline (first implementation)

**Behavior**:
- All servers: Same config file
- Disable operation: ADD `"disabled": true` field
- Enable operation: REMOVE `"disabled"` field
- Server without field (or `disabled: false`) = enabled

**Best for**:
- Clients with native disable field support
- Single-file configs (no shadow file needed)
- Better UX (disabled servers visible with reason)
- Version control friendly (single file)

**Future Consideration**: Windsurf and potentially other clients could migrate to InlineEnableDisableHandler if their native clients support it. This would simplify the implementation and improve UX.

