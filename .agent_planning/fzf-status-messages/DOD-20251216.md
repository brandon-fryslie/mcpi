# Definition of Done: FZF Status Messages

**Topic:** Redirect operation logs from stdout to fzf status field

## Acceptance Criteria

- [ ] **AC1**: When using `mcpi fzf` and pressing ctrl-a to add a server, no stdout flash occurs - the operation completes silently
- [ ] **AC2**: After any operation (add/remove/enable/disable), the fzf header updates to show the operation result (success/failure message)
- [ ] **AC3**: The status message persists in the header until the next operation or until fzf is closed
- [ ] **AC4**: Error messages are clearly visible in the status area (e.g., "✗ Server not found")

## Sprint Scope

1. Add `--fzf-mode` flag to CLI commands (add, remove, enable, disable)
2. Implement status file mechanism for passing results to fzf
3. Update fzf bindings to use silent execution and display status in header

## Out of Scope

- Other CLI output modes (JSON, etc.)
- Backwards compatibility concerns for non-fzf interfaces
- Changes to non-fzf TUI adapters
