# Plan: FZF Status Messages

**Created:** 2025-12-16
**Topic:** Redirect operation logs from stdout to fzf status field

## Problem Statement

When using `mcpi fzf` and performing operations (add/remove/enable/disable), there's a brief flash (~1/3 second) where log messages appear on stdout before fzf refreshes. These messages are unreadable and create a poor user experience.

The root cause is that fzf's `execute()` binding runs CLI commands that use `console.print()` to stdout. When fzf resumes, the output disappears.

## Solution Overview

Since `mcpi fzf` will be the primary interface, we'll:

1. Add a `--fzf-mode` flag to CLI commands that suppresses stdout and writes status to a file
2. Update fzf adapter to read status from file and display in header/border area
3. Use fzf's `change-header` action to show operation results

## Implementation Details

### 1. Status File Mechanism

Create a simple status file at `~/.mcpi_fzf_status` that stores the last operation result:
- Single line format: `[timestamp] [status] [message]`
- Example: `1702756800 SUCCESS ✓ Added filesystem to project-mcp`
- Example: `1702756800 ERROR ✗ Server not found in registry`

### 2. CLI Changes

Add `--fzf-mode` flag to `add`, `remove`, `enable`, `disable` commands:
- When set, suppress all `console.print()` calls
- Write final status to `~/.mcpi_fzf_status`
- Exit silently (no stdout/stderr except fatal errors)

Implementation approach:
- Create a context manager or utility to redirect console output when in fzf mode
- Or: Check flag at start of command and conditionally print

### 3. FZF Adapter Changes

Update bindings to use `--fzf-mode` and display results:

```
--bind 'ctrl-a:execute-silent(mcpi add {1} --scope "$(cat ~/.mcpi_fzf_scope)" --fzf-mode)+reload(mcpi-tui-reload)+change-header($(mcpi-tui-status))'
```

Key changes:
- Use `execute-silent` instead of `execute` (suppresses output)
- Add `change-header` to show operation result
- Create `mcpi-tui-status` script to read and format status file

### 4. Status Display Script

New console script `mcpi-tui-status`:
- Reads `~/.mcpi_fzf_status`
- Formats for fzf header display
- Combines with standard header (scope, keybindings)

### 5. Header Format

```
MCPI | Scope: project-mcp | Last: ✓ Added filesystem
^S:Chg-Scope ^A:Add ^R:Remove ^E:Enable ^D:Disable
^I/Enter:Info  Esc:Exit
```

## Files to Modify

1. `src/mcpi/cli.py` - Add `--fzf-mode` flag to add/remove/enable/disable
2. `src/mcpi/tui/adapters/fzf/adapter.py` - Update bindings to use silent execute + status
3. `src/mcpi/tui/adapters/fzf/scripts.py` - Add status reading/writing functions
4. `pyproject.toml` - Add `mcpi-tui-status` console script entry point

## Alternative Considered

Using `execute(... >/dev/null 2>&1)` - This hides output but loses status information entirely. Users wouldn't know if operations succeeded.

## Testing

1. Run `mcpi fzf`
2. Add a server with ctrl-a → should show "✓ Added ..." in header
3. Remove a server with ctrl-r → should show "✓ Removed ..." in header
4. Try invalid server → should show "✗ Error ..." in header
5. Enable/disable servers → verify status updates correctly
